The same plan, built by Qwen.

While Claude agents built and shipped iteration 2 (the board), agents on the hackathon kit's team model built the same plan in parallel, to see how an open-weight model on our own GPU compares. Nothing from this track merges.

Setup: Qwen3 Coder 30B (4-bit) on the GPU box, reached through the kit's gateway by Claude Code in headless mode, inside the kit's dev container: a fresh clone per task, a default-deny firewall, a private Postgres, no credentials, an explicit tool allowlist. Each run's work is judged by the kit's verifier (make check plus its incident checks) and the backend tests, never by the agent's report.

Where it stands

The experiment is over. The Claude track shipped all of iteration 2 in about two hours (first PR opened 19:32, the refreshed tour merged 21:29). In six and a half hours (18:47 to 01:18), 30 runs, and about 110 million input tokens, the Qwen track finished no task. Two tasks, the stream form and the landing page, passed the gate, and every review found them not done. Tags stayed blocked after ten runs. The backend never committed in eight runs, so the overview and the balances page, which depend on it, never started.

The gate alone is not proof of done. The stream form passed make check twice, and the whole gate once, while its form still could not save a new stream: the hidden minimum and maximum were empty, and editing would have stored amounts a hundred times too large. The landing page passed while skipping, for the third time, the validation messages and the readme it had been asked for, and its new copy and sample chart were not there.
