# Notes on iteration 1 (Sat 2026-09-26)

Erik's notes on the first build of kriket (whiteboard items 0 to 3, live at https://app.26.cohack.tetl.ca,
tour at https://26.cohack.tetl.ca/tour/1/), gathered on day 1 and kept here in his words. More were still
coming when this file was written; it is a running list, not a final one.

## After reviewing the tour

- Overall, this app feels like "just a spreadsheet". That makes sense, since it is what we asked for when we
  said steps 0 to 3. In the next iteration we need to think much more carefully about how the product fits
  in the market, is actually usable, and solves holistic problems for real-world people with real-world
  habits.
- The voice memo where we got feedback after pitching the idea has great insights that we need to use and
  keep thinking about further. (In substance: the differentiator over a spreadsheet is how low-lift the data
  entry is, statement upload or read-only bank access versus punching everything in; people either give an
  app everything or refuse to type, and that balance is the hard part; the persona is the young person with
  variable income who does not track anything today, not the receipt-logging enthusiast; security and trust
  matter as much as features; the three concepts, income streams, expense streams, and goals, are simple to
  understand, so keep them.)
- Does Tags need its own page? Having only shades of green for tags is limiting.

## After using the live app

1. Logged in, tried to add a balance: the Save button did nothing. No way of knowing it worked.
   (Checked afterwards: the save does land and the stored balance updates; with no streams yet the empty
   state hides the stat cards and the chart, so nothing on screen changes. A feedback gap, not a data bug.)
2. On the add income and add expense screens the date picker should be shadcn's, but it uses the browser
   default, which breaks the styling.
3. If only the usual amount is entered, minimum and maximum must equal it. Don't make me fill out each one.
4. Tags should allow for any color, add a color picker (that is shadcn styled - or at least not browser defaults)
5. The preset tags should change to: pay cheque, bill, groceries, investment. (two income streams and tow expense streams)
6. expenses should be orange this color will be called expense-orange.
7. when the user's funds / projected funds go below zero on the overview graph the area below the graph should be expense-orange. We need to highlight that this is a negative state
8. In general expenses should be expense-orange in most cases unless for accessibility / usability reasons this cannot be the case. We need to keep the contrast between earning and losing
9. Make the "coming up" page show one month at a time, allow users to flip through the months - do not let the users go to times before they started using the application 
10. The current balance point is new - was not discussed and part of the original plan - but it is a welcome feature. To flesh this out a couple of things can be done
    1. setting your current balance should be closer to the top because this is where the projections start
    2. we should store the user's balances, and allow them to see how their projections have been changing - flipping through balances
11. On the rendered projection graph, there should be points on the graph for each occurrence of an income stream or an expense stream
